# 修复：self_evolve 的 lint 闸门被项目基线告警永久卡死

## 问题（已实测确认）

`_evolve_lint` 用 `ruff check <改动文件>` 并要求返回码为 0。但本仓库主力文件**自带历史告警**：

```
deepseek_client.py 基线：25 个告警（UP031×7、SIM105×16、B023×2）
```

后果：**任何改到 `deepseek_client.py` 的自我进化都会被永久拦住**，哪怕只是改一行的合法修复。函数 docstring 写的是「规避项目基线告警淹没，让进化聚焦改动本身」——**意图是对的，实现没做到**：它只对单文件跑 check，从未与基线做过差分。

这不是理论问题。本次 Bing 302 修复就撞在这上面：
```
编译：通过
lint：ruff 检查发现问题   ← 卡在这里，其实是基线的 25 个历史告警
导入：导入冒烟失败
测试：退出码 2
```
我不得不用「原路径临时分支」证明补丁**零新增告警**（仍是同样 25 个、同样规则集），然后改走手工分支+合并。自我进化链对这个项目最重要的文件**完全失效**。

## 方案

把「要求零告警」改为「**只拦新增告警**」：

1. 对改动后的工作区内容跑 `ruff --output-format=json`；
2. 用 `git show HEAD:<rel>` 取改动前内容，以 `--stdin-filename <rel>` 交给 ruff 跑一次，得到基线；
3. 按 `(规则代码, 消息文本)` **分组计数**比对：某组数量超出基线数量时，超出的部分才算新增；
4. 有新增才失败并逐条列出（行:列 + 规则 + 消息），无新增则明确回「无新增问题」并说明豁免了多少基线告警。

新文件（HEAD 中不存在）基线为空集，等价原语义；取不到基线（无 git / ruff 基线跑挂）时**保守降级为全量判定**并在输出里写明降级原因，不静默放行。

## 两个踩过的坑（都写进代码注释了，避免后人重蹈）

**坑 1：按行号比对会大量误报。**
第一版把行号纳入比对键。但重写函数会让后续行号整体位移，于是同一条历史告警在新位置被当成「新增」——实测误报 22 条。改为按 `(code, message)` 分组计数后，行号位移完全不影响判定。

**坑 2：把 HEAD 版写到临时目录再检查，ruff 读不到项目配置。**
临时目录里跑同一份文件：
```
临时目录跑 HEAD 版: 227 告警，规则 B023/BLE001/DTZ005/F401/FURB167/... （14 种）
项目根跑 HEAD 版:    25 告警，规则 B023/SIM105/UP031 （3 种）
```
27 倍差距，差分彻底失效（基线只认到 9 条，剩下 16 条全被误判为新增）。改用 `--stdin-filename` 让 ruff 始终以项目根为 cwd，问题消失（实测 stdin 方式得 25 条，与项目根完全一致）。

## 验证（5 个场景，全部符合预期）

在临时分支上把提案文件放进生产路径，直接调 `_evolve_lint` 实测：

| 场景 | 输入 | 结果 |
|---|---|---|
| A 无新增 | 只重写 `_evolve_lint` + 新增 `_evolve_ruff_json` | ✅ `无新增问题（ruff 差分通过：改动后 25 个告警，全部与基线一致）` |
| B 注入 1 处新告警 | 末尾加一个 `try/except/pass` | ✅ `发现 1 个新增问题：6066:5 SIM105 ...`（另有 25 个基线告警不计入）|
| C 全新文件 | 新建模块，含未用 import + try/except/pass | ✅ 报出 2 条：`1:8 F401`、`5:5 SIM105` |
| D 非 py 改动 | `["README.md"]` | ✅ `（本次改动无 Python 文件，跳过 lint）` |
| E 空列表 | `[]` | ✅ 同上 |

关键对照：场景A 与场景B 只差一处注入，闸门精确区分「历史包袱」与「本次引入」。

仅 `deepseek_client.py`：

## 风险提示

1. **计数差分有边界**：如果一次改动**删掉**了 3 处历史告警、同时**新增** 2 处同规则告警，净值仍是减少，差分判定会取「超出基线数量」的部分，不会报出——考虑到基线是历史存量，这可能漏掉个别新增。保守替代方案是「按规则集合判定」（只要出现基线没有的规则就报），但那会漏掉「同规则多一处」这一最常见的坏味道。这里选计数法，并接受该边界。
2. **基线依赖 git**：无 git 环境下不生效（降级为全量判定，行为等同旧版），不会变宽松。
3. **性能**：多跑一次 ruff。实测单文件约 1 秒，对 120 秒超时闸门无实质影响。

## 为什么没用 self_evolve 自动落地
