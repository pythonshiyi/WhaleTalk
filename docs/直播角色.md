# 直播角色 v2（本地 P0）

> 目标：**一个持续在线的 AI 主播**，而不是「收到一条弹幕 → 回一句台词」的机械接口。
> 当前阶段只跑本地（模拟弹幕 + 舞台页），不接平台、不推流。

## 与旧实现的区别

| | 旧实现（v3.28） | v2（P0） |
|---|---|---|
| 触发 | 只有送礼/弹幕才说话 | 每秒 tick：**回 / 自主开麦 / 沉默** |
| 人格 | 只取角色卡的 `name` | 角色卡**全量**（性格/背景/说话方式/边界） |
| 记忆 | 无 | 观众关系（到访次数/常客）+ 最近台词 + 当日统计 |
| 动机 | 打赏 → 吃饱（讨饭） | 互动 → 精力/情绪；礼物只是事件之一 |
| 注意力 | 有求必应 | 打分后**可以不理**（刷屏/复读/过期弹幕） |
| 表达 | 单句 TTS | 同上，但语音异步、可回填 |

## 分层

```
平台适配器 / 模拟器
      │ LiveEvent（danmaku / gift / enter / follow / like / sc）
      ▼
   EventBus ──► Director（每秒一次决策）
                   │  注意力打分（attention.py）
                   ├─ 值得回 → Actor（角色卡 + 房间状态 + 最近台词 → 一句台词）
                   ├─ 冷场够久 → Actor.self_talk（自主开麦）
                   └─ 都不 → 沉默
                   ▼
              stage.publish ──► 台词上屏 / HUD 轮询 / TTS 异步回填
                   ▼
              Room（观众关系 / 精力 / 情绪 / 话题 / 短期记忆）
```

| 模块 | 职责 |
|---|---|
| `live/events.py` | 事件模型与线程安全总线；平台无关 |
| `live/room.py` | 直播间状态：观众关系、精力、情绪、话题、最近台词；跨场只保留关系 |
| `live/attention.py` | 显著性打分：提问/点名/新观众加权，刷屏/复读/过期降权 |
| `live/prompts.py` | 角色卡 + 直播规则 + 房间状态 → 提示词 |
| `live/actor.py` | 生成台词（多轮上下文、合规过滤、复读检查、兜底） |
| `live/voice.py` | TTS（复用 api_server 的三级引擎，后台合成） |
| `live/stage.py` | 当前台词 / `audio_seq`，HUD 数据源 |
| `live/director.py` | 决策循环：限速、待回队列、自主开麦、精力门槛 |
| `live/simulator.py` | 本地剧本：新观众/常客复读/礼物/键盘侠刷屏/长冷场 |
| `live/simulate.py` | 命令行跑通（无需 HTTP） |

## 本地怎么跑

```bash
# 1) 纯命令行（最快验证"像不像活的"）
python -m live.simulate --seconds 60 --speed 2 --idle 12
python -m live.simulate --dry          # 不调模型，只验证链路

# 2) 带舞台页（立绘占位 + 字幕 + 弹幕流 + 开始/停止模拟）
python web_app.py --port 8745
# 浏览器打开 http://127.0.0.1:8745/live/stage.html
# 点「开始模拟」；OBS 可直接把这页当浏览器源
```

API：

| 端点 | 说明 |
|---|---|
| `GET /live/data` | 免 token（OBS 用）：账本快照 + 最近事件 + 当前台词 + 房间状态 |
| `GET /live/audio/<hash>.mp3\|wav` | 免 token 的语音（`<audio>` / OBS 带不了 Authorization 头；走 `/v1/tts/audio` 会 401） |
| `GET /live/stage.html` | 舞台页（静态，`live_hud/`） |
| `GET /v1/live/room` | 房间状态（观众/精力/情绪/话题） |
| `POST /v1/live/sim` | `action=start|stop|step|status`，本地模拟控制 |
| `POST /v1/live/gift` / `chat` | 手工事件：导演未运行时同步回一句；运行时入总线 |

## 关键设计取舍

- **沉默是一等公民**：`attention.MIN_REPLY_SCORE` 以下一律不回。真人直播大部分时间不说话，
  "每条都回"正是机械感来源。
- **限速不等于丢问题**：限速窗口内到来的高价值事件进 `_hold`（最多 3 条），窗口过后补回；
  超过 25 秒的弹幕直接过期（不追着回旧话题）。
- **精力/情绪与钱解耦**：`Room.energy` 由互动与时间驱动；`live_state` 只保留打赏账本。
- **会话级字段不落盘**：`live_room.json` 只保留观众关系/话题/议程，事件、台词、
  限速时间戳在启动时清空（否则新一场会被上一场"刚说过话"卡住）。
- **合规内建**：索要礼物/自我暴露/旁白动作在 `live/safety.py` 统一过滤，生成后再兜底。

## 下一步（P1+）

1. **B 站弹幕适配器**：`room_init` → WebSocket `broadcastlv.chat.bilibili.com/sub` →
   `DANMU_MSG` / `SEND_GIFT` / `INTERACT_WORD` / `LIKE_CLICK` / `SUPER_CHAT_MESSAGE`
   翻译成 `LiveEvent`，其余各层不动（先只读观察）。
2. **TTS 流式 + 打断**；立绘换 Live2D + 口型。
3. **OBS/ffmpeg 推流**：舞台页作浏览器源，或直接合成帧推 RTMP。
4. **跨场记忆**：常客称呼、梗库、上次聊到哪（接 `persona_memory` / `brainkit`）。
5. 平台合规：AI 内容标注、内容审核、未成年人保护。
