# 能力协议（Capability Protocol）

> 本文是**新能力接入的唯一标准**。想给鲸语加一项工具能力，看这一篇就够。
> 当前协议版本：`whaletalk.tool/1`（实现见 `capability.py`）。

---

## 1. 为什么有这个协议

v3.16 之前，插件工具和内置工具走两条互不相交的路：

| 维度 | 内置工具 | 插件工具（旧） |
|---|---|---|
| 注册 | `@tool()` → 六层注册表 | 写 `user_tools.json` |
| 执行 | 注册处统一过 `tool_hooks` | `_run_custom_tool` 直发 HTTP |
| 能力地图 | 有分组 / 预激活 | **没有**（模型找不到） |
| 横切 | 快照 / 信任 / 出网账本 / 降级 | 全无 |
| 健康度 | 有 | 无 |
| 卸载 | —— | 改写 JSON 文件 |

结果不是「插件功能少」，而是**插件工具从来不是一等公民**：装了，模型却看不见。

v3.17 起两者并入同一张注册表（`toolkit._REGISTRY`），唯一区别是 `source`
（`core` / `capability`）。**插件退化为装载单位，能力才是被管理的东西。**

---

## 2. 三个词，别再混用

| 词 | 指什么 | 用户看到的名字 |
|---|---|---|
| **能力**（capability） | 一项可被模型调用的原子工具 | 「能力」 |
| **能力包**（manifest） | 一组能力的装载单位（一个 JSON 文件） | 「已安装 N 项能力」 |
| **指令**（prompt/skill） | 提示词资产，不参与 function calling | 「指令」 |

界面上**不出现「插件」这个词**（旧页面文案逐步下线）：来源只是详情里的一个字段。

---

## 3. manifest 规范

放在 `data/capabilities/<名字>.json`，启动时自动装载。

```json
{
  "api": "whaletalk.tool/1",
  "meta": { "name": "财报速读", "version": "1.0.0", "author": "你" },
  "capabilities": [
    {
      "name": "p_finance_brief",
      "description": "读取本地财报文件并提炼三项关键指标（模型靠这句话决定是否调用）",
      "parameters": {
        "type": "object",
        "properties": { "path": { "type": "string", "description": "财报文件路径" } },
        "required": ["path"]
      },
      "exec": { "type": "builtin_ref", "tool": "read_file", "args_map": { "path": "path" } },
      "io": { "max_chars": 8000 },
      "budget": { "timeout": 30, "write": false, "idempotent": true },
      "perms": { "tools": ["read_file"], "files": [] },
      "groups": ["📊 数据与文档"],
      "phrases": "读财报要点",
      "preactivate": [["财报", "年报", "季报"]],
      "examples": [{ "args": { "path": "C:/tmp/a.pdf" }, "expect": "非错误" }]
    }
  ]
}
```

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `api` | ✅ | 必须等于 `whaletalk.tool/1`。核心升级时会据此判兼容 |
| `capabilities[].name` | ✅ | 必须 `p_` 开头（小写字母数字下划线）。**禁止遮蔽内置工具** |
| `capabilities[].description` | ✅ | 给模型看的触发场景，不是宣传语 |
| `capabilities[].parameters` | ✅ | OpenAI function parameters，`type=object` |
| `capabilities[].exec` | ✅ | 四种执行体之一（见 §4） |
| `capabilities[].groups` | ✅ | 至少一个分组。可复用已有组名，如 `🔧 系统与基础` |
| `capabilities[].perms` | ✅ | 最小权限声明（见 §5）；**调用期强制** |
| `capabilities[].io.max_chars` | 建议 | 输出上限，超出截断并注明 |
| `capabilities[].budget` | 建议 | `timeout`（秒，默认 60）/ `write` / `idempotent` |
| `capabilities[].phrases` | 建议 | 动作短语（能力地图里的一句话说明） |
| `capabilities[].preactivate` | 建议 | 关键词组，命中即预激活（省一次 `activate_tools` 往返） |
| `capabilities[].examples` | 建议 | 金样，用于装机自检 |

**为什么不声明 `groups` 会被拒装**：smart_tools 模式下模型只能靠「组名 + 代表作」发现能力。
没有分组的能力永远进不了能力地图 —— 那正是旧插件「有实现、没人用」的根因。

## 4. 四种执行体

### 4.1 `builtin_ref` —— 复用内置能力（最推荐）

```json
"exec": { "type": "builtin_ref", "tool": "read_file", "args_map": { "path": "path" } }
```

`args_map` 语义：`{被复用工具的参数名: 本能力的参数名}`；省略则原样透传。
它的价值在于**重组而不复制**：把 `read_file` + `pdf_extract` 组合成「读财报」，实现零重复。

### 4.2 `http` —— 声明式 API

```json
"exec": { "type": "http", "url": "https://api.example.com/w", "method": "GET", "headers": {"X-Key": "..."} }
```

- `perms.net` 必须为 `true`；
- URL 会过 SSRF 硬底线（私网/链路本地/保留段拦截），回环默认放行。

### 4.3 `cli` —— 命令行

```json
"exec": { "type": "cli", "command": "ffmpeg", "args": ["-version"] },
"perms": { "cli": ["ffmpeg"] }
```

- 命令必须在 `perms.cli` 名单里（按 basename 比对，不支持通配）；
- 仍会叠加用户的 shell 黑名单（`permissions.check_shell`）；
- 超时由 `budget.timeout` 控制，子进程超时会被终止。

### 4.4 `python` —— 进程内代码

```json
"exec": { "type": "python", "entry": "main:run" },
"perms": { "python": true }
```

- 模块从**能力包所在目录**加载（不污染 `sys.path`，改文件即重载）；
- 入口 `def run(**kwargs) -> str`（也兼容 `def run(args: dict) -> str`）；
- **必须显式声明 `perms.python: true`**：它等价于本机任意执行，没有任何沙箱。

---

## 5. 权限：声明即最小权限

| 键 | 类型 | 含义 |
|---|---|---|
| `net` | bool | 允许出网（`http` 执行体必需） |
| `tools` | 数组 | 允许复用的内置工具名（`builtin_ref` 必需） |
| `cli` | 数组 | 允许执行的命令名 |
| `python` | bool | 允许运行自带代码 |
| `files` | 数组 | 允许访问的路径根（为空时仍过用户黑名单，但不受根限制） |

两层校验，缺一不可：

1. **声明层**（装机时）：`exec` 与 `perms` 不匹配 → 整包拒装；
2. **调用层**（每次执行）：路径落在声明根内、命令在名单内、`net`/`python` 已声明。

未声明 = 无权限，不存在「默认允许」。

## 6. 预算与熔断

| 机制 | 行为 |
|---|---|
| 超时 | 超过 `budget.timeout` 返回「错误：执行超时」。**注意**：Python 线程无法被中断，超时后工作线程仍会跑完（结果丢弃）——这是不做子进程 RPC 的代价 |
| 熔断 | 连续失败 3 次后进入 60s 冷却，期间直接返回错误、不再真的执行 |
| 截断 | 输出超过 `io.max_chars` 会被截断并注明原始长度 |
| 记账 | 失败/超时/权限拒绝都会进 `degrade` 账本（组件名 `capability.<工具名>.*`） |
| 快照 | `budget.write=true` 时自动挂 `snapshot` 钩子（写操作可恢复） |
| 出网账本 | `perms.net=true` 时自动挂 `egress` 钩子 |

---

## 7. 装载 / 卸载 / 热替换

| 操作 | 效果 |
|---|---|
| 装载 | 注册进同一张注册表 → 六层视图**当场重建**（模型下一轮就能看到） |
| 热替换 | 同名包重复装载 = 先卸旧再装新，epoch 递增 |
| 卸载 | **温和失效**：epoch 失效使旧句柄返回「已卸载」，但已进入执行的调用不打断；六层立即重建 |
| 冲突 | 与内置或其它包重名 → **整包拒装**（不做部分装载） |

接口：

```
GET  /v1/capabilities                 # 能力包 / 能力清单 / 健康度
POST /v1/capabilities                 # {"action":"load|reload|unload", "file"|"plugin_id"}
```

`file` 只接受 `data/capabilities/` 内的**文件名**，不接受路径——否则端点即任意装载入口。

## 8. 装机自检清单

装一个能力包之前，逐条确认：

- [ ] `api` = `whaletalk.tool/1`
- [ ] 每个 `name` 以 `p_` 开头，且不与内置工具同名
- [ ] 每个能力都有 `groups`（否则进不了能力地图）
- [ ] `exec.type` 与 `perms` 匹配（http↔net / cli↔cli / builtin_ref↔tools / python↔python）
- [ ] `description` 写的是**触发场景**，不是功能宣传（模型只看这句话）
- [ ] 给了 `examples` 至少一条，并且实际跑通过
- [ ] 写操作的能力标了 `budget.write=true`（否则不会自动快照）

## 8.5 参数 / 配置 / 硬边界：三层分工

能力一旦"可配置"，第一个问题就是**谁来决定**。鲸语的答案是固定三层，不靠自觉：

| 层 | 谁决定 | 存放位置 | 例子（公众号写作） |
|---|---|---|---|
| **配置层**（持久偏好） | 用户 | `data/wechat_writer.json`（设置页读写） | 字数区间 1200–2500、受众 general/geek、信源分组、是否走代理 |
| **参数层**（单次任务） | 模型填，配置兜底 | 能力 manifest 的 `parameters` | 用户说"写 2000 字" → `chars=2000`；没说 → 空值走配置 |
| **硬边界层**（不可协商） | 代码 | 执行体 / `io` / `budget` / `perms` | 只产草稿永不自动发布；字数被夹进配置区间；质检不过不落盘；信源只取配置里的组 |

判断标准只有两句：

- **谁掌握长期偏好，默认值就归谁。** 把 `chars=2000` 写死进 manifest，这个能力包换个用户就是错的。
- **谁承担不可逆后果，硬边界就归谁。** "发不发""抓哪些站"不能交给模型——那是外部动作与 SSRF 面。

被边界夹住时**必须说出来**，不能静默：用户要 800 字而配置下限 1200，工具会把字数按 1200 执行，
并在结果里写「目标字数 800 超出你的配置区间 1200–2500 字，按 1200 字执行」。

## 9. 与旧 `.wtplugin` 的关系

旧格式（`contents.tools` 的 HTTP 工具）仍可安装，但它们走旧旁路，**不享受**本章任何治理。

迁移期用桥函数转换：

```python
import capability, json
legacy = json.load(open("old.wtplugin", encoding="utf-8"))
manifest = capability.adapt_legacy(legacy)      # v2 tools → v3 capabilities
ok, errs = capability.validate_manifest(manifest)
```

转换后旧字段不再生效（工具仍在，只是换了入口），确认无引用即可删除。

## 10. 核心工具预算：可以加，但要留痕

有了能力主干，加功能有两条路，**成本不同**：

- 加内置工具：永久增加每次对话的 schema 预算与门禁面；
- 加能力包：可停用、可卸载、可单独排障。

`tools/check_tool_budget.py` 不禁止新增，只要求**一次辩护**：

```bash
python tools/check_tool_budget.py                  # CI 用：新增/删除内置工具即红灯
python tools/check_tool_budget.py --waive "理由"    # 接受变更，写入 core_tool_budget_log.txt
```

理由要回答一个问题：**为什么这项能力不能做成能力包？**
（典型正当理由：需要被 `builtin_ref` 复用为基元、需要在无数据目录时可用、属于上下文装配本身。）
