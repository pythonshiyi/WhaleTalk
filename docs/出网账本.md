# 出网账本（`egress.py`）

> 模块：`egress.py`（接线：`tool_hooks.py` 全局钩子 + 工具声明）
> 设计立场：**不阻断，但可审计**。

## 一、问题：安全模型不对称

| 方向 | 现状 |
|---|---|
| 入网 | 有 SSRF 硬底线（私网 / 链路本地 / 保留段拦截 + DNS 预解析防重绑定），不依赖用户配置 |
| 出网 | 此前 **0 处**审批与审计——`send_email` / `im_send` / `send_webhook` / `publish_draft` 内部都没有闸口 |

一个能读全盘、能发邮件 / Webhook、默认零审批的执行体，「数据不出本机」只覆盖了
**存储与监听**，没覆盖 egress。

## 二、设计：与信任内核同构 —— 不阻断，但可审计

刻意**不**加拦截：与「默认自由 + 用户掌权」的立场冲突，而且 `run_python` 一个
`requests.post` 就绕过去了——工具层设卡只挡君子。改为：

- 每次**带内容**出网留痕：`通道 / 目的地 / 字节数 / 内容摘要(sha256 前 16 位) / 结果`
- **默认不存明文内容**（只留摘要与大小）——留痕是为了可审计，不是再造一份数据副本；
  需要时 `store_preview` 可开（≤200 字符）
- **目的地脱敏**：URL 去掉 query / fragment / userinfo（query 常含 token）
- 达阈值时向模型注入「出网留痕」，让它**知道自己往外发了什么**并如实告知用户

## 三、接线：一个钩子 + N 处声明

这是 `tool_hooks` 管线价值的兑现——**工具体零改动**：

```python
# tool_hooks.py：一个全局钩子
hook("post", "egress", _hook_egress, 30)

# 出网工具各加一行声明
@tool(..., hooks=('egress',))
```

判定与抽取全在 `egress.EGRESS_SPECS`（通道 / 目的地键 / 载荷键 / 只读排除规则），
**新增出网工具只需加一行**，不用碰钩子。

读操作被显式排除（有测试锁定）：`agent_mail(action=list)`、`call_api(method=GET)`、
无 body 的 API 调用、`webdav(action=list)` 都不记账。

## 四、明确不做

- **不阻断任何出网**：只让它可见、可审计、可回溯。
- **不在账本里存明文内容**：默认只留摘要与大小。

## 五、验证

`tests/test_egress.py` 覆盖记账/脱敏/只读排除/失败结果；`island_check` 无孤岛；
实机可查 `GET /v1/status` 的 `egress` 摘要与 `GET /v1/context` 的 `egress` 明细。
