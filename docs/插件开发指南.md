## 1. 插件是什么

**插件** = 单个 `.wtplugin` 文件（纯 JSON），声明一类能力并提供入口。安装后：

- 自动合并进身份库（工具 → 用户工具、技能 → 指令库、流程 → 流程库）
- 应用型插件（v2）自带 Python 代码，`/触发词` 直接执行，不走 AI
- 卸载 = 精确移除本插件声明的条目 + 删除代码目录（**零残留**）

```json
{
  "format": "wtplugin",
  "version": 2,
  "meta": { "...": "..." },
  "contents": { "...": "..." }
}
```

---

## 2. 文件格式

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | ✅ | 必须是 `"wtplugin"` |
| `version` | number | ⚠️ | `1`（基础）/ `2`（含 `app`+`files` 的应用型） |
| `meta` | object | ✅ | 元数据（见 §3） |
| `requires` | array | 可选 | 依赖的 pip 包名列表（安装时自检） |
| `contents` | object | ✅ | 能力声明（见 §4） |

---

## 3. 元数据（meta）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | ✅ | 插件名（唯一，卸载按名字匹配） |
| `description` | string | 建议 | 插件功能描述（展示 + AI 理解） |
| `author` | string | 可选 | 作者 |
| `version` | string | 建议 | 如 `"1.0.0"` |
| `icon` | string | 可选 | emoji 图标 |
| `trigger` | string | 应用型必填 | 主触发词，如 `"/飞侠"` |
| `triggers` | array | 可选 | 附加触发词，如 `["@飞侠", "/巡航"]` |

**触发词规则**：`/名称` 或 `@名称`，输入框命中即执行（可带参数）。触发词必须以 `/` 或 `@` 开头，不含空格。

## 4. 能力声明（contents）

`contents` 至少要包含 `tools` / `skills` / `workflows` / `scenario` / `app` 中的**任意一个**。

### 4.1 工具（tools）

**HTTP 工具**——声明自定义 API 工具，AI 可调用（无需写代码）：

```json
"tools": [
  {
    "function": {
      "name": "plugin_get_weather_v2",
      "description": "获取城市天气（插件版）",
      "parameters": {
        "type": "object",
        "properties": {
          "city": { "type": "string", "description": "城市名，如 北京" }
        },
        "required": ["city"]
      },
      "endpoint": "https://example.com/api/weather",
      "method": "GET",
      "headers": { "X-Key": "xxx" }
    }
  }
]
```

规则：
- `function.name`：a-z/A-Z/0-9/下划线/连字符，最长 64
- `function.endpoint`：必填（工具执行时对端点发请求，参数自动注入）
- `method`：GET / POST（默认 GET）；POST 时参数作为 JSON body

### 4.2 技能（skills）

**提示词模板**——AI 收到即切换到该技能模式：

```json
"skills": [
  { "name": "周报生成", "text": "你是周报助手，按【本周完成 / 下周计划 / 风险求助】输出…" }
]
```

- `name` 必填（≤40 字符），`text` 必填（提示词，可含 `{{TEXT}}` 占位符）

### 4.3 流程（workflows）

**多步流程**——一条消息按步骤逐步执行：

```json
"workflows": {
  "每日巡检": {
    "steps": [
      "检查服务器健康状态",
      { "text": "汇总问题并报告", "recipe": "已验证巡检链" }
    ]
  }
}
```

- `steps` 为数组：每项是**指令字符串**（发给 AI 执行）或 `{text, recipe}` 对象（recipe 引用已验证工具链 patterns）

### 4.4 场景（scenario）

**一键场景**——安装后可直接代入对话背景：

```json
"scenario": {
  "name": "数据分析师",
  "thinking": "high",
  "system_prompt": "你是一位数据分析师，输出前先给结论…",
  "enabled_tools": ["database_query", "chart_data"]
}
```

### 4.5 应用（app + files）——v2

**应用型插件**——自带 Python 代码，触发词直接执行（绕过 AI）：

```json
"contents": {
  "app": {
    "type": "local",
    "entry": "main:run"
  },
  "files": {
    "main.py": "# 插件主入口\nimport json\ndef run(arg_text=''):\n    ...",
    "data.py": "..."
  }
}
```

规则：
- `app.type`：仅支持 `"local"`
- `app.entry`：`module:func` 或 `module:class:func`（从 `files` 中的 `.py` 模块加载）
- `files`：`{相对路径: 源码}`，**至少一个 `.py`**；路径禁止 `..`（防逃逸）
- 入口函数签名：`def run(arg_text: str) -> str`，参数为触发词后的文本，返回字符串（回显聊天区）

## 5. 完整示例：打招呼应用插件（v2）

`hello.wtplugin`：

```json
{
  "format": "wtplugin",
  "version": 2,
  "meta": {
    "name": "打招呼应用",
    "description": "演示应用型插件：/hi 触发，问候传入的名字",
    "author": "WhaleTalk",
    "version": "1.0.0",
    "icon": "👋",
    "trigger": "/hi",
    "triggers": ["@hi"]
  },
  "contents": {
    "app": {
      "type": "local",
      "entry": "main:run"
    },
    "files": {
      "main.py": "def run(arg_text=''):\n    name = arg_text.strip() or '朋友'\n    return f'你好，{name}！我是礼貌的鲸语小插件。'"
    }
  }
}
```

安装后输入 `/hi 小明` → 聊天区回显「你好，小明！我是礼貌的鲸语小插件。」

## 6. 编写本地应用（app 类型）

- **入口函数**：`def run(arg_text="") -> str`。返回的字符串直接回显；抛异常则回显错误
- **代码限制**：`files` 只写 `.py`；运行时从 `plugins/<slug>/` 加载（`sys.path` 不污染，uninstall 整目录删除）
- **性能**：首次调用加载，后续按 mtime 增量重载（改代码即生效）
- **可获取 API**：函数内 `import` 项目模块（如 `deepseek_client`）以复用平台能力
- **示例：带复用平台能力**（`main.py`）：

```python
def run(arg_text=""):
    import deepseek_client as dc
    result = dc.get_date()
    return f"现在的时间是：{result}。你说：{arg_text or '无'}"
```

## 7. 校验规则速查（validate_plugin）

| 检查项 | 规则 |
|---|---|
| format | 必须 `"wtplugin"` |
| meta.name | 非空 |
| contents | 至少含 tools / skills / workflows / scenario / app 之一 |
| tools[] | 每条必须有 `function.name` + `function.endpoint` |
| skills[] | 每条必须有 `name` + `text` |
| workflows | 必须是 `{流程名: {steps: [...]}}` |
| app | `type="local"`；`entry` 必须 `module:func` 或 `module:class:func` |
| files | 对象；至少一个 `.py`；路径禁 `..` |

非法插件不能安装（`parse_plugin_file` + `validate_plugin` 双检）。

## 8. 安装 / 卸载 / 停用机制

| 操作 | 行为 |
|---|---|
| **安装** | 插件文件写入 `data/plugins/<slug>.wtplugin` → `contents` 合并进 user_tools.json / prompts.json / workflows.json（条目带 `_source: plugin:<slug>` 标记）→ 应用型插件写 `data/plugins/<slug>/` 代码目录 |
| **停用** | 移除 `_source` 标记的条目，保留插件文件与代码目录（可再启用） |
| **启用** | 重新合并 `contents` 条目 |
| **卸载** | 移除标记条目 + 删除插件文件 + **整目录删除** `plugins/<slug>/`（零残留） |

**版本语义**：`version` 升级后再次安装会覆盖旧条目（同名覆盖）；降级同理。

## 9. 插件工坊（AI 设计工坊）

插件中心提供 **AI 插件设计工坊**（插件中心 → 画廊 → 「🧩 AI 插件设计工坊」按钮），零代码生成插件：

**使用流程**：
1. 填写**需求**（如"做一个定时巡检网站可用性的插件，异常时推送 webhook"）
2. 可选填**插件名**、**类型**（应用型/工具/技能/流程/自动判断）
3. 点「✨ AI 生成」→ LLM 生成 `.wtplugin` JSON（应用型会附带可运行 `main.py` 骨架）
4. **预览并编辑** JSON（可手工调整）
5. 点「💾 校验并安装」→ 后端 `validate_plugin` 校验 → 自动安装 → 立即生效

**校验失败自动重试**：AI 生成若校验不过，后端会用错误信息引导 AI 修正重生成一次。

**说明**：
- 工坊生成的插件与手写插件完全等价（同一 validate / apply 链路）
- 应用型生成 `app + files`（`main.py` 提供 `def run(arg_text='') -> str` 骨架）
- 生成后可在「已安装」tab 停用/卸载/查看详情
- 会话内也可直接让 AI 用 `create_plugin` 工具生成（较早期方式）

## 10. 调试与发布

1. **本地调试**：
   - 把 `.wtplugin` 放进 `sample_plugins/`（刷新即出现在画廊）
   - 或直接放到 `data/plugins/`（出现在已安装列表）
2. **应用型插件调试**：改 `files` 源码后重启鲸语或重进会话（mtime 增量重载）
3. **发布**：分享 `.wtplugin` 文件即可；第三方插件市场接入见「开放生态」章节（规划中）

## 11. 最佳实践

1. **插件做单一职责**：一个插件解决一类问题（如"飞侠"= 巡航），不要大杂烩
2. **应用型插件优先**：纯 Python 逻辑走 `app` + `files`（性能好、可控、零 AI 成本）；需要 AI 推理时再用工具/skills
3. **工具描述写清楚**：AI 靠描述决定何时调用——`description` 写明触发场景
4. **敏感操作降级**：工具端点用 https；密钥类信息不要写在插件文件里（用 secret_store）
5. **版本化**：每次修改提升 `version`，方便区分新旧
6. **`requires` 声明依赖**：安装时自检缺失依赖并提示安装命令
