# P1 收口：出网账本 · 记忆单一门面

> 对应提交：`feat(arch): P1 出网账本 + 记忆门面`
> 模块：`egress.py` · `memory_facade.py`（接线：`tool_hooks.py` 钩子 / `context_providers.py` Provider / `write_memory`）

两项的共同出发点：**P0 解决了"横切关注点没有收口"，P1 解决"两个最不对称的边界"**——
安全模型入强出弱，记忆体系有写无治。

---

## 一、出网账本（`egress.py`）

### 问题：安全模型不对称

| 方向 | 现状 |
|---|---|
| 入网 | 有 SSRF 硬底线（私网/链路本地/保留段拦截 + DNS 预解析防重绑定），不依赖用户配置 |
| 出网 | **0 处**审批与审计——`send_email` / `im_send` / `send_webhook` / `publish_draft` 内部都没有闸口（只有 `agent_mail` 有两阶段确认） |

一个能读全盘、能发邮件/Webhook、默认零审批的执行体，"数据不出本机"只覆盖了
**存储与监听**，没覆盖 egress。

### 设计：与信任内核同构 —— 不阻断，但可审计

刻意**不**加拦截：与「默认自由 + 用户掌权」的立场冲突，而且 `run_python` 一个
`requests.post` 就绕过去了——工具层设卡只挡君子。改为：

- 每次**带内容**出网留痕：`通道 / 目的地 / 字节数 / 内容摘要(sha256 前16位) / 结果`
- **默认不存明文内容**（只留摘要与大小）——留痕是为了可审计，不是再造一份数据副本；
  需要时 `store_preview` 可开（≤200 字符）
- **目的地脱敏**：URL 去掉 query / fragment / userinfo（query 常含 token）
- 达阈值时向模型注入「出网留痕」，让它**知道自己往外发了什么**并如实告知用户

### 接线：只用了一个钩子 + 7 处声明

这是 P0-1 工具钩子管线的价值兑现——**工具体零改动**：

```python
# tool_hooks.py：新增一个全局钩子
hook("post", "egress", _hook_egress, 30)

# 7 个出网工具各加一行声明
@tool(..., hooks=('egress',))
```

判定与抽取全在 `egress.EGRESS_SPECS` 里（通道 / 目的地键 / 载荷键 / 只读排除规则），
**新增出网工具只需加一行**，不用碰钩子。

读操作被显式排除（有测试锁定）：`agent_mail(action=list)`、`call_api(method=GET)`、
无 body 的 API 调用、`webdav(action=list)` 都不记账。

## 二、记忆单一门面（`memory_facade.py`）

### 问题一：无血缘 → 提示注入可持久化

`_chat_harvest` 每次对话后自动提炼 0-3 条写入长期记忆并注入每一轮，而外部网页内容
只靠 `_wrap_external` 的文本标记隔离。于是这条链成立：

```
抓网页 → 内容进上下文 → 我复述 → harvest 提炼 → 变成永久记忆 → 以后每轮都注入
```

**根本缺陷是模型无法区分「用户明说的」与「我自己推断的」**，于是把自己推断的
东西当作用户前提。

修法：每条记忆带 `origin`（user / agent / web / system / unknown）。注入时：

```
[长期记忆]（无标注 = 用户明说或早期记录；〔推断〕= 你自己提炼的，不得当用户前提）
- 用户偏好中文回复
- 〔推断〕用户下周要交报价单
- 〔来自外部内容〕某网页称该库已弃用
```

`_chat_harvest` 写入时固定 `origin="agent", confidence=0.4`。

### 问题二：无作废 → 新事实被静默丢弃

原「近重复合并」只并 `tags/type/entities`，**新的 `value` 被丢掉**——写
"用户偏好英文回复" 之后，生效的仍是 "用户偏好中文回复"。

修法：`supersedes` / `superseded_by` 双向链接 + `status`，**可回溯、可 `restore`**。
取代**只在显式传 `supersede_key` 时发生**（按旧条目的 id / key / 完全相同文本匹配）；
冲突提示会带回旧条目 id，模型据此二次调用即可完成取代。

### 关键设计决策：作废只认显式 key，绝不按相似度

这是本项目**实测之后的结论**，不是保守取舍。用 `similarity()`（中文 bigram +
拉丁词 Jaccard）在真实记忆对上的得分：

| 记忆对 | 相似度 | 期望 |
|---|---|---|
| 偏好中文回复 ↔ 偏好英文回复 | 0.556 | 应作废 |
| 每周五备份 ↔ 每周五备份（改为周四） | 0.636 | 应作废 |
| 纯静态架构 ↔ 改用 Next.js 架构 | **0.154** | 应作废 |
| 项目**A**用 PG ↔ 项目**B**用 PG | **0.600** | **绝不能**作废 |

**相似度无法区分「应作废」与「绝不能作废」**：0.556 要作废而 0.600 不能；
而真正该作废的「架构迭代」只有 0.154（几乎不含共同词）。

因此：
- **自动作废只走显式 `supersede_key`**——精确、可控、可解释；
- **相似度只用于冲突提示**（≥0.55），提示里给出可执行的解决方式
  （"如需替换请用同一 key 重写，或先 invalidate"）——把判断交还给具备判断能力的角色；
- 这张表被固化成回归测试（`test_similarity_measurement_is_stable`），
  防止后人「顺手」加回相似度自动作废。

### 向后兼容

沿用 `{enabled, facts:[{key,value,type,ts,entities,relations}]}` 结构与既有字段名，
**只新增** `origin/confidence/status/supersedes/superseded_by/superseded_at/reason/id`。
旧数据**读时补默认值，不改写文件**（有测试断言磁盘未被改写）。

> 字段命名：用 `origin` 而非 `source`——`memory_store.py` 的 canonical schema 里
> `source` 已经是「数据来源」（memory.json / brain / knowledge），不能占用。

### 范围界定

只管 `memory.json` 这一层。**不接管大脑记忆**（`brain/memories/memory.jsonl`）——
它已有 `source/importance/supersedes` 体系。`write_memory` 的实体别名归并与
`_brain_sync_memory` 同步保持原样。

## 三、过程中被测试抓出的自身缺陷

1. **相似度阈值的假设是错的**：原设计打算「同 type 且高相似（≥0.75）自动作废」，
   实测发现 0.556（应作废）低于 0.600（绝不能作废）→ 方案整体推翻，改走显式 key。
2. **缺依赖被当成失败报警**：Provider 依赖未注入时按异常计入 `degrade`，会变成
   一串永远刷屏的假降级告警。改为 Provider 显式声明 `deps`，缺失按「依赖未注入」
   跳过（记回执、不计失败）。
3. **按下标而非派生 id 定位条目**：条目被其它写入方改写后派生 id 会变，用 id
   反查会静默失配。改为按下标就地作废 + 固化 id。
4. **`write_memory` 新增参数未同步 schema**：被 `audit_tools.py --strict` 抓出
   （「签名有参数 schema 无」）——门禁再次证明价值。
5. **测试文件被重复追加**：`cat >>` 执行了两次，重复的测试函数名会**静默覆盖**
   前者（pytest 只跑最后一个）。已去重并加了重复函数名检查。
6. **端到端抓到最严重的一个**：默认 key（"自动记忆"）被当成取代依据后，两条毫不
   相干、只是都没填 tags 的记忆会互相作废——实测中「用户明说的偏好」被一条无关的
   agent 推断顶掉了。**取代改为必须显式传 `supersede_key`**，默认 key 不再参与。
7. **成败判定**：工具约定「失败返回 `错误：…` 而非抛异常」，`ctx.ok` 不等于
   「真的发出去了」→ 账本按结果前缀修正，发送失败也照记（ok=False）。

## 四、明确不做

- **不阻断任何出网**：与信任内核同一立场，只让它可见、可审计、可回溯。
- **不在账本里存明文内容**：默认只留摘要与大小。
- **不做语义级自动作废**：需要向量语义信号，超出本层；且实测显示词面相似度不可用。
- **不接管大脑记忆**：两套体系边界保持清晰。
